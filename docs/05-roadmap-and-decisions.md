# 05｜实施路线与决策记录（Agent 日志看板 MVP）

> **首期已明确收缩（2026-10-10）**：**Agent 登记 → Run 日志采集 → 看板展示**。原先跨系统业务 Task/Outcome、复杂 Connector、上岗双审批、工时/ROI 与财务对账**退出本期**。以 [17 MVP 规格](17-agent-log-dashboard-mvp.md) 为准。

## 1. 已确认决策

| ID | 决策 | 来源 / 时间 | 影响 |
| --- | --- | --- | --- |
| **D0** | 首期**集团管理层优先** | 用户，2026-10-09 | 看集团 Agent 资产和技术运行全貌，非堆砌运维明细 |
| **D10** | 原始 HTML 上传仓库，按现有布局**1:1 还原** | 用户，2026-10-10 | 原文件保持不可改，UI-F0 保留四页视觉与演示交互 |
| **D11** | 正式前端 **Vue 3 + TypeScript + Vite** | 用户，2026-10-10 | 独立 frontend/，Demo 与正式 Provider 分离 |
| **D12** | **极简 MVP：登记 Agent、采集 Agent 日志、展示看板** | 用户，2026-10-10 | 复杂员工治理、源业务结果回执/对账、节省工时、ROI、自动编排都退出首期 |

**范围解释建议**：一 Agent 登记 = 一数字员工卡；执行一次 = 一条唯一 Agent Run；Run 成功 ≠ 业务成功。这个简化口径可在获取第一批真实日志样本后做字段级细化。

## 2. 推荐交付顺序（不承诺工期）

| 阶段 | 交付 | DoD |
| --- | --- | --- |
| UI-F0（可与后端并行） | Vue 3 原型 1:1 复刻、Demo Provider、原型视觉回归 | 四页、五场景说明、9 人 Demo、六图和交互、五 viewport 验收；原 HTML SHA 不变 |
| BE-A Agent 登记 | 1 张 Agent 表、CRUD API、简单维护界面 | 新增、编辑、启停，平台/环境/源 Agent ID 唯一，不影响远程 Agent 运行 |
| BE-B Run 日志采集 | HTTP 上报、1 张 Run 表（可选 Log 表）、查询分页 | 有认证且脱敏；同一 Run 重复上报只计一次；能展示失败和最近采集时间 |
| UI-F1 实际看板 | Agent 列表、Run/成功率/耗时、趋势、排行与详情，替换 Demo | 同时间窗指标能对齐；无日志显示无数据；真实 Run 不与 Demo 混算 |

**最小后端建议**：一个服务 + MySQL；视实际 Agent 平台能力决定由调用方上报还是单个只读日志适配。没有理由首期建通用 Connector 管理门户和多服务基础设施。

## 3. MVP 验收

- [ ] Agent 登记/编辑/停用/查询正常，按部门展示；
- [ ] 每个 Agent 唯一关联一个源 Agent 标识和来源环境；
- [ ] Run ID + Agent ID 幂等，同一 Run 上报多次只计一次；
- [ ] 能查看成功、失败、运行中、取消 Run，技术成功率分母只含成功/失败；
- [ ] 无法采集时间/耗时时不造数据，表明来源与最近采集时间；
- [ ] 总览、单 Agent 列表、日期趋势、排行一致，能定位失败 Run；
- [ ] 日志不存原始 Prompt、客户/员工隐私，API 认证/分页/最小读权限；
- [ ] Vue 复刻原型布局，演示运行和真实数据在不同 Provider/环境；
- [ ] 生产页面不宣称业务任务成功、真实工时节约、已结算成本或 ROI。

## 6. 当前尚需现场核实（仅是接入条件）

- 第一批 Agent 源平台和测试方式；
- 是否有稳定 Run ID、状态、时间戳、错误日志和 Token 用量；
- 能否由调用方 HTTP 上报或提供只读日志查询接口；
- 公司现有登录/权限系统和日志保留要求。

这些问题不改变“只做三件事”的范围。原型 HTML 公开包含业务流程，需确认发布授权；生产日志/令牌不能推送到公开仓库。
