## 1. 总体策略

**首期优先集团管理层：先连接已有能力，再证明数据可信，最后评价业务价值。**

第一阶段优化目标是“管理层看懂且相信经营结论”，而不是“监控中心秒级动画更流畅”。主入口优先四张成果/价值卡、业务趋势和部门/场景贡献；监控中心保留异常摘要与必要追踪，不作为开发主线。

数字员工看板应被当成“集团数字员工的运营账本”。看板第一天可以没有漂亮的工时趋势，但不应把随机演示数当作运营结果。

## 2. 分阶段里程碑（建议；加入已确认的 UI-F0 先复刻要求）

**顺序约束**：原型 HTML 已归档，首轮前端开发 **UI-F0 先 1:1 还原页面视觉与交互**，不以“新设计的管理驾驶舱草图”替代。后端采集与指标定义可并行；UI-F1 才替换数据，UI-F2 再按集团管理层优先优化展示。具体总排期需重新估算，原先 6–8 周仅供参考。



| 阶段 | 建议迭代 | 输出物 | 验收门槛 |
| --- | --- | --- | --- |
| S0：原型基准与口径 | 首个迭代 | **原始 HTML 完整归档（已完成）**；UI-F0 视觉/交互基准与截图；两场景任务口径、SSO 数据范围及接入协议 | 原文件 Git 哈希校验、截图/交互验收范围冻结；业务事件口径进入评审 |
| S1：采集与目录 | 第 2–3 周 | 目录/员工详情基础能力；签名事件接收、幂等、Task/Run、源系统回执、最小监控 | 两个试点场景可回放真实业务任务结果；不依赖前端模拟；重试不重算 |
| S2：UI 复刻 + 数据接入 | 后续迭代，排期待定 | **UI-F0 按原型逐模块视觉还原**；UI-F1 接入数据与身份权限；保留 2 一级导航、员工详情、五场景与监控 | 与原型布局/交互一致；Demo/正式数据隔离，已核验数可下钻；越权测试通过 |
| S3：价值核验 + UI-F2 评审 | 后续迭代，排期待定 | 工时基线/成本对账/统计快照；管理层四主卡、布局调整等候选优化逐项审议 | 原型布局修改有明确审批；指标可溯源、估算与已核验分开 |
| S4：五场景扩展 | 第 7–8 周及以后 | 采购/巡检/排班 Adapter、SLA 与业务回执、规范化案例展示 | 每个新增场景独立通过任务定义和数据对账验收 |

**投入假设（供估算）：** 1 名前端、1 名后端、场景业务开发按需参与，测试/运维/业务 Owner 兼职配合；若基础 IAM、数据库、消息与监控无法复用，需要重新排期。

## 3. 首期为什么选两类场景

- **菜品调整**：典型“自然语言 → 参数校验 → 业务工具调用 → 业务状态变化”，覆盖审批、高影响变更、同步回执与重复事件。
- **智能报销**：典型“文档输入 → 结构化匹配 → 校验 → 人审 → 外部业务提单”，覆盖长流程、回调、人审和复杂成功状态。
- 两个样本可以检验**短/长流程、同步/异步、自动/人工协作**。通过后再扩充采购（内容交付）、巡检（高频批量）、排班（约束求解）三个模式。

## 5. 必须进行的测试

| 测试 | 可接受的结果 |
| --- | --- |
| 同一业务任务因超时自动重试两次 | 一条 Task，多个 Run；任务与收益只计一次 |
| 超过 24 小时后回调完成/乱序送达 | 原始事实不丢失，任务状态合法，受影响聚合可重算 |
| Agent 报“成功”，实际源业务写入失败 | 业务最终状态失败，不误报为完成 |
| 正常等待财务审核 | 显示“待人工”，不能算完成或失败；审核时长可分离 |
| Kafka/Webhook 停止上报 | 明确 STALE/采集异常；前端不继续增加虚拟数据 |
| 员工迁移部门 | 历史指标按当时归属或明确公布的重算策略处理 |
| 部门 A 访问部门 B 任务明细/导出 | 必须受后端权限拒绝 |
| 业务报告中的工时与成本 | 可以追溯到具体任务、基线版本、usage 与分摊方法 |
| 相同筛选的首页、列表、详情 | Task 总量可核对，不因查询维度出现无法解释的差异 |
| 告警静默/指派/关闭 | 操作人、原因、时间、状态审计完整 |

建议将这些场景整理成自动化集成测试 + 几条业务回放测试集，作为任何员工“已核验上线”的条件。

## 6. 风险与控制

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 内部多个平台的任务口径不同 | 任务量与节省工时被夸大 | Task/Run 分离、场景单位口径签署 |
| 未取得实际业务回执 | “模型说成功”误判业务完成 | 源系统确认事件，缺失时显示待核验 |
| 公开仓库传播内部原型或业务数据 | 合规与信息泄露 | 只公开脱敏方案；私有仓库存接口/流程细节 |
| 把运行状态与生命周期混淆 | 管理层错误理解上线规模 | 生命周期、接入验证、近期心跳分离 |
| 未校准基线就计算 ROI | 不可审计的夸大收益 | 样本与签署留档，释放产能与现金节约分离 |
| 为“统一”强行重构已有 Agent | 集成周期过长 | 优先采集事件/回执；按场景适配 |
| 看板故障阻断业务系统 | 生产事故 | 业务与采集解耦，发送端缓存/可重试 |
