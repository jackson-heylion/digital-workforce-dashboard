# 13｜UI-F0 / UI-F1 质量门禁、测试矩阵与验收方法

> **状态：建议的可执行测试标准；团队尚未运行或通过这些测试。**
>
> 原型单一视觉基线：[prototype/index.html](../prototype/index.html)（Git Blob `92d6df5d024a665cb88fcff9724fcb8ac1787225`）；技术路线已确认 Vue 3 + TS + Vite；详见 [ADR](10-frontend-adr.md)、[交互契约](12-frontend-interactions.md)。

## 1. 验收原则

- **不能“看着像”就结束**：每个页面既要截图对照，也要实际进行路由、用户操作、图表、文件预览和动态事件的交互回归。
- **视觉对照不是每个随机像素完全相等**：原型动态图表动画、实时日志、字体和浏览器渲染有天然差异；必须固定时钟/演示数据/窗口/浏览器版本/设备缩放，屏蔽不可确定区域，再比较结构与几何位置。
- **不能为了提高截图得分而隐藏页面内容**：先保证相同文字、业务卡片、图表、流程和交互完整，再降低剩余差异。
- **正式模式零数据不是正常数值 0**：生产必须严格按数据质量标记渲染，不能被 Demo Provider 的原型数字回填。
- **不能要求真实后端 API 作为 UI-F0 通过的前置条件**：UI-F0 测试使用 Demo Provider；UI-F1 再启用 API 对接与安全性验收。

## 2. 固定测试条件

- Viewports：桌面 `1440×900`、`1280×800`；平板 `768×1024`；移动 `390×844`、`375×812`。
- 对照：同一 Chromium/浏览器版本、100% 缩放、1x `deviceScaleFactor`、相同字库、无浏览器扩展干扰。Mac/Windows 字体不同应单独留基线。
- Locale `zh-CN`；时区 `Asia/Shanghai`；测试冻结时间（样例）`2026-09-23T09:47:05+08:00`，日期仅用于复现原型演示，不是当前生产时间。
- 数据集使用**从原型移植的 9 名演示员工、5 个场景和静态图表输入**；保留样本顺序和文字。
- 图表等待真实 `finished` 或动画关闭后再截图；不要用固定短 sleep 赌渲染成功。
- 动态执行流截图时固定时钟/随机数并暂停下一次推送；不得因此破坏正常 Demo 可滚动行为。

## 5. 可执行 E2E 场景（验收口径）

### E2E-01 导航与浏览器历史

- 初始路由展示总览，只有总览高亮；进入监控后监控高亮。
- 进入员工详情或场景页时，顶部仍高亮总览。
- “返回总览”、浏览器前进/后退、直接访问 URL 后加载员工详情正确（URL 深链属于推荐的路由增强）。
- 输入未知员工 ID 或不存在场景时，给明确空状态或回退，不显示另一个员工的内容。

### E2E-02 九位员工和五场景

- 首页卡片合计 9，按 5 个部门原型顺序分组。
- 每个员工点击“运行与绩效”，标题、版本、部门、指标联动一致。
- 仅 5 个原型标杆员工具备“场景演示”；点击后对应 `sc-1..sc-5` 内容可见。
- 五个快捷锚点、返回顶部可用，场景说明表格完整。

### E2E-03 图表与响应式

- 首页 `c-hours/c-cost/c-top` 3 张，详情 `c-detail-trend/c-detail-hours/c-detail-cost` 3 张；图表数据/轴标签/单位按原型。
- 切换员工、导航、调整尺寸时图表不空白、不串数据、不重复初始化；组件卸载释放实例。
- 移动宽度 375/390px 时导航可滚动，工作流预览、告警处理入口可触达；表格横向滚动不破坏页宽。

### E2E-04 工作流与告警

- 上传 PNG/JPG/PDF 后预览；第二个文件替换第一个；可移除、重新上传、在新标签打开。
- Demo 告警“处理”和“忽略”仅改变对应条目，显示演示反馈，页面整体状态更新可观察。
- UI-F1 正式模式在无权/接口错误时不应假装处理成功；上传文件须服务端安全验证和持久化（**不属于 UI-F0**）。

### E2E-05 动态事件

- Demo 首条消息及之后的 6 秒节奏由受控测试时钟推进；任务数变化符合原型最终视觉效果。
- 离开/进入详情和场景多次后，刷新不能出现多重订阅或多个并行模拟 Timer。
- 正式模式禁用 `DemoTicker`，没有真实上报时只能显示可解释的空状态。

### E2E-06 可信度与权限（UI-F1）

- 没接入业务数据：员工为未核验/未接入，数据卡 `value=null` 不显示数字。
- 真实成功、失败、审批中、重试，分别对应合适的任务和 KPI；Run 不增加 Task 计数。
- 源系统断连：状态 `STALE` 并展示 `as_of`。
- 部门 A 的 token 无法查到部门 B 的详情、报告、事件，包括手工修改查询参数。

## 6. 最小 CI 门禁（拟实施）

```text
Pull Request
  ├─ Verify source prototype blob unchanged
  ├─ Install dependencies with checked-in lockfile
  ├─ Typecheck + ESLint
  ├─ Unit & component tests
  ├─ Vite production build
  ├─ Playwright navigation/interaction
  ├─ Playwright visual snapshots (fixed environment)
  └─ Publish test report/artifact for review (do not publish sensitive business data)
```

- 建议 `frontend/package.json` 提供 `dev`, `build`, `typecheck`, `lint`, `test:unit`, `test:e2e`, `test:visual`。
- GitHub Actions runner/浏览器版本/缓存策略需在具体工程落实时固定；本次仅定义门禁，不声称工作流已安装。
- 如测试截图包含原型中的内部业务流程，CI artifacts 权限、保存周期要随仓库公开状态审查；公开仓库默认不应该公开上传生产业务截图。
- 不使用私有密钥运行纯 Demo 视觉测试，生产接入类测试单独在授权环境中执行。
