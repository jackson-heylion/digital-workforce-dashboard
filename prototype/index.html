场景一 · 智能报销助手 ↑ 顶部 真实在用 财务中心

① 账单接入各物业提供的不规则账单（费用明细 / 供应商 / 收款账号等原始信息）
→
② 抽取与匹配抽取费用原始信息 → 自动匹配对应门店
→
③ 规则转换每条费用按规则转换为标准费用类型 + 圈定合同 + 匹配付款计划行
→
④ 提单生成拼接打款摘要 + 做账备注，输出可确认提交的标准提单
→
⑤ 员工确认最终确认（规则内免确认，直接流转）
→
⑥ 提交财务审核汇联易提单 → 财务审核 · 全程留痕可追溯
配置项内容
输入各物业不规则账单（发票 / 账单 PDF / 邮件附件，钉钉群机器人接收）
执行体百炼智能体应用（OCR 抽取 + 门店匹配 + 费用规则引擎）
业务系统汇联易费控平台（开放平台 API：提单整单/拆单、单据提交）+ 合同 / 付款计划数据
知识库费用类型对照规则、门店映射表、合同与付款计划台账（RAG 可溯源）
人审节点匹配失败 / 超预算 / 无合同圈定 → 转人工；规则内免确认
反馈方式处理进度回钉钉消息卡片；异常推送待办

这个场景回答了什么问题

  • 把物业账单「人工读账单 → 手工建单」的活交给机器人：抽取、匹配、转换、拼接一步到位；
  • 标准提单直接进汇联易，财务只审"该审的"，打款摘要与做账备注自动拼接，减少返工；
  • 「员工确认 → 财务审核」两段式人机协作，关键动作留痕、合规可审计。
对接参考：汇联易开放平台 sdk.huilianyi.com（标准接口封装 + 业务场景模板）；汇联易原生支持钉钉集成。

免确认规则（决策已定稿）grill-me 审核采纳 · 归财务中心配置

规则项定稿口径
规则配置权财务部（平台留操作日志，变更可审计）
适用单低风险小额合规单（金额阈值内 / 发票校验通过 / 无历史异常）
生效方式免确认规则上线前由财务负责人签字确认；规则内单据直接流转至财务审核
审计标记免确认单全部标记「免确认」，财务可一键复查
红线：资金支付类动作永远不设免确认
报销审核只免「提交流转确认」，实际支付 / 出款环节必须有财务人工审批，两层职责分离。
  • 员工仍可随时查看处理进度（钉钉消息卡片）；
  • 规则调整走平台「免确认规则配置」，无需改代码。

场景二 · 菜品调整 ↑ 顶部 真实在用 信息中心

① 用户 Agent 发起"把 XX 菜品下架 / 调价 / 改名"
→
② Agent 解析确认识别意图与参数（菜品 ID / 调整类型 / 生效时间）
→
③ 调用业务系统菜品系统 API 完成调整（已对接，无需人工进后台）
→
④ 自动反馈结果回 Agent / 钉钉（成功 / 失败原因 + 生效信息）
→
⑤ 变更留痕写入审计 + 同步门店 / 渠道菜单
配置项内容
用户入口钉钉内 Agent（智能助理 / 机器人）
执行体百炼智能体（工具调用 + 意图解析 + 参数校验）
业务系统菜品 / 菜单业务系统 API（查询、新增、修改、上下架、生效时间）
权限控制仅菜品管理员角色可发起；高影响变更（全部门店）二次确认
反馈方式调整结果 + 生效信息回 Agent / 钉钉消息卡片
审计变更前后值、操作人、时间全记录，可回溯

这个场景回答了什么问题

  • 运营不再需要登录后台逐页操作，一句话完成改价、下架、改名；
  • Agent 对接业务系统 = 从"聊天"到"办事"，是数字员工最有代表性的能力；
  • 变更留痕 + 权限校验，避免误操作，审计可追责。
要点：Agent 侧的每个工具调用都通过平台连接器转发，统一记账与留痕。

菜品调整权限与冲突规则（决策已定稿）grill-me 审核采纳 · 归运营中心

角色可执行动作
菜品管理员发起调价 / 改名 / 上下架（单店或指定门店）
运营负责人审批高影响变更（全部门店 / 下架 / 大额调价）
平台审计全部变更留痕（前后值 / 操作人 / 时间）

冲突与防误操作规则

  • 同菜品同一生效时间重复变更 → 直接拒绝；
  • 生效时间处于营业高峰前 2h 内的变更 → 强制人工确认；
  • 下架操作默认全部门店需审批，单店可放宽；
  • Agent 每次调整先做「权限 + 冲突」双重校验再调 API。
规则机制说明：免确认与权限冲突规则为「报销 / 菜品」已定稿示例；采购情报、门店巡检、稽查排班的业务规则（数据源准入、告警阈值、排班约束）按各自业务配置，统一由平台配置中心收口，详见《研发对接清单》第 8 章。

这个场景回答了什么问题

  • 采购不再逐站点查价、手工汇总——Agent 一次问答给到价格、走势、供应全貌；
  • skill 沉淀为可复用能力，报告产出从"小时级"到"分钟级"；
  • 平台统一记账：每次查询 / 报告都是可度量的数字员工工作量。
已建成：Agent + Skill 已发布，可出报告 / 查询 / 汇总信息。

场景四 · 门店巡检助手 ↑ 顶部 真实在用 运营域

① 多系统对接已对接所有可监控系统（设备 / 能耗 / 安防 / 环境等监控信息）
→
② 统一接入监控信息统一汇入巡检中枢，归一化处理
→
③ 规则巡检按规则自动巡检，异常识别与分级
→
④ 统一管理统一看板 + 异常告警 + 整改闭环（不再分散登录各系统）
配置项内容
接入范围已对接的全部可监控系统（设备 / 能耗 / 安防 / 环境等）
执行体百炼智能体（数据归一 + 规则引擎 + 告警判定）
输出统一巡检看板 / 异常告警 / 整改任务（钉钉推送）
闭环异常识别 → 告警 → 派单整改 → 复核关闭
受益方门店运营、区域管理、设备维保

这个场景回答了什么问题

  • 从"人跑多个系统看监控"到"一个入口统管全部门店监控"；
  • 异常自动识别、分级告警、整改闭环，巡检覆盖率和时效显著提升；
  • 监控信息统一接入 = 后续所有门店数字化能力的数据底座。
已建成：所有可监控系统已对接，监控信息统一接入本系统管理。

场景五 · 稽查智能排班助手 ↑ 顶部 真实在用 内审部

① 规则输入稽查人员技能 / 资质 / 工时上限 / 法规合规等复杂约束
→
② 排班引擎复杂规则求解，自动给出最佳排班方案
→
③ 排班表生成输出最优稽查排班表（覆盖 / 公平 / 合规多目标）

配置项内容
输入人员技能 / 资质 / 工时上限 / 法规合规 / 门店覆盖要求
执行体百炼智能体 + 排班规则引擎（复杂规则求解）
输出最佳稽查排班表（人工复核后发布）

已建成：通过复杂规则给出最佳排班表。口径说明：今日处理次数含排班生成、调整与查询。
